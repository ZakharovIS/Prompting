# Prompting — Агент с явной моделью памяти (Memory Layers)

В проекте реализована явная 3-слойная модель памяти ассистента с раздельным хранением и явным управлением тем, какие данные попадают в каждый слой.

## Что реализовано

### 1) Краткосрочная память (Short-term)
- **Назначение:** текущий диалог.
- **Где хранится:** в `ChatAgent` (`fullHistory`) + summary старой части диалога.
- **Что попадает:** сообщения пользователя и ассистента текущей сессии.
- **Как влияет на ответ:** используется как основной контекст запроса к LLM.

### 2) Рабочая память (Working)
- **Назначение:** данные текущей задачи.
- **Модель:** `WorkingMemory(goal, keyFacts, openQuestions)`.
- **Где хранится:** отдельное поле `workingMemoryJson` в `chat_sessions`.
- **Что попадает:**
  - текущая цель (последний релевантный user intent),
  - ключевые данные по задаче,
  - открытые вопросы.
- **Как влияет на ответ:** добавляется отдельным `system` сообщением в контекст перед генерацией ответа.

### 3) Долговременная память (Long-term)
- **Назначение:** профиль пользователя, договорённости, факты.
- **Модель:** `LongTermMemoryItem(category, content, createdAt)`.
- **Где хранится:** отдельная таблица Room `long_term_memory`.
- **Что попадает:** предпочтения (`preference`), факты (`fact`), решения (`decision`).
- **Как влияет на ответ:** добавляется отдельным `system` сообщением как долговременный профиль (только при релевантности).

## Разделение хранения по слоям

- **Short-term:** оперативная память агента (`ChatAgent`).
- **Working:** `chat_sessions.workingMemoryJson`.
- **Long-term:** таблица `long_term_memory`.

Таким образом, слои не смешиваются и сохраняются раздельно.

## Изменения в БД

- Версия Room повышена до **v3**.
- Добавлена миграция `2 -> 3`:
  - `ALTER TABLE chat_sessions ADD COLUMN workingMemoryJson TEXT NOT NULL DEFAULT '{}'`
  - `CREATE TABLE long_term_memory (...)`
- Добавлены:
  - `LongTermMemoryEntity`
  - `LongTermMemoryDao`

## Изменения в коде

- Добавлены модели:
  - `app/src/main/java/ru/zis/prompting/agent/MemoryModels.kt`
- Обновлён агент:
  - `ChatAgent` теперь явно ведёт short/working/long-term память,
  - формирует контекст ответа с учётом всех слоёв.
- Обновлён репозиторий:
  - `ChatRepository` сохраняет/загружает `workingMemory`,
  - отдельно сохраняет/загружает долговременную память.
- Обновлён `ChatViewModel`:
  - восстановление всех слоёв при старте,
  - сохранение всех слоёв после ответа,
  - методы `shortTermMemoryDump()`, `workingMemoryDump()`, `longTermMemoryDump()` для проверки.

## Проверка на экране (UI)

В `TopAppBar` добавлены 3 кнопки:
- **💬** — краткосрочная память
- **🔧** — рабочая память
- **🧠** — долговременная память

По нажатию открывается `AlertDialog` с содержимым соответствующего слоя.

Это позволяет визуально проверить:
1. какие данные попали в каждый слой,
2. что слои разделены,
3. как слои влияют на формирование ответов.
