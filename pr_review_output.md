## 🐛 Потенциальные баги
- **PR-добавляет новый файл, но diff обрезан (TRUNCATED)**: конец `main()` не виден. В текущем фрагменте код обрывается на `lexical_se...` — есть риск, что в реальном файле остался незавершённый идентификатор/строка и файл не запустится/не импортнётся. Нужен полный diff, чтобы подтвердить.
- **`cmd_diff()` использует `git diff --stat HEAD~1`**: на первом коммите/в shallow clone `HEAD~1` может отсутствовать → `_run_git` вернёт `(git error: ...)`, но `cmd_diff()` это не обрабатывает и выведет строку “Diff …” + текст ошибки как “статистику” (не фатально, но поведение некорректное по UX).
- **`_run_git()` проглатывает любые ошибки и возвращает строку** вида `(git error: ...)`: далее `get_git_context()` использует это значение как `branch/last_commit`, из-за чего в system prompt может попасть “(git error: …)” вместо “unknown”. Это ломает формат/смысл git-контекста.
- **Импорты `shlex` не используются**, а также в показанном фрагменте не используется `Path`? (Path используется). Не баг, но признак недочищенного кода.
- **`LocalLlmClient.generate()` ожидает ответ в поле `response`**. Без контекста по `local_llm_service` нельзя подтвердить формат. Если сервис возвращает, например, `choices[0].message.content`, то будет всегда пустая строка.
- **Лексический поиск `_tokens()` режет токены короче 3 символов**: для частых запросов по аббревиатурам/коротким терминам (API, RAG, PR) часть сигналов теряется → retrieval может быть неожиданно пустым.

## 🏗️ Архитектурные проблемы
- **Смешение ответственности в одном скрипте**: CLI, git-MCP команды (`/branch`, `/files`, `/diff`), RAG (RouterAI), fallback lexical retrieval и клиент локальной LLM — всё в одном файле. Это усложнит тестирование и сопровождение.
- **Дублирование/расхождение с существующим интерфейсом `rag_query.py`**: проект уже имеет `rag_query.py` как основной CLI для запросов. Новый `dev_assistant.py` частично повторяет конфиг (модели, index path, local.properties), но вводит другие режимы и параметры (timeout/max_retries) — возможна конфигурационная “развилка” и разные дефолты.
- **Жёстко зашитые параметры retrieval/rerank в `answer_help()`**: `rerank_threshold=0.35`, `low_relevance_threshold=0.20`, `rewrite_query=True` и т.д. — без вынесения в args/конфиг это трудно подбирать и объяснять пользователю.
- **Надёжность git-интеграции**: все git-команды выполняются через `subprocess.run(["git", ...])` без проверки, что мы в git-репозитории, и без явного управления cwd. В зависимости от того, откуда запускают скрипт, поведение может быть нестабильным.

## 💡 Рекомендации
- **Прислать полный diff/файл**: сейчас ключевая часть `main()` обрезана; без неё нельзя проверить, что CLI-цикл команд, ветвление local/routerai и инициализация `LexicalSearcher` действительно корректны.
- **Исправить обработку ошибок `_run_git()`**:
  - либо бросать исключение и обрабатывать его на уровне команд,
  - либо возвращать `""` и/или структурированный результат (ok/err), чтобы `get_git_context()` мог ставить `"unknown"` вместо “(git error: …)”.
- **Сделать `cmd_diff()` более безопасным**: использовать `git diff --stat HEAD` (или просто `git diff --stat`) либо fallback на `HEAD` при ошибке `HEAD~1`.
- **Убрать неиспользуемые импорты (`shlex`)** и проверить, что нет “висячих” зависимостей/мертвого кода.
- **Согласовать формат ответа local LLM**: либо документировать ожидаемый контракт (`{"response": "..."}`), либо поддержать несколько форматов (например, `response`, `text`, `choices`).
- **Вынести retrieval-настройки в аргументы CLI** (thresholds, rewrite_query, rerank on/off), чтобы поведение было управляемым и сравнимым с `rag_query.py`.
- **Разделить модули**: git-утилиты в отдельный файл, local-llm клиент отдельно, lexical search отдельно. Это позволит проще тестировать (особенно `LexicalSearcher.top_k` и обработку индекса).
- **Уточнить пути**: сейчас `resolve_local_properties_path()` ищет `local.properties` относительно `parent.parent` от файла (т.е. “корень проекта”), но имя переменной `script_root` вводит в заблуждение. Переименовать в `project_root` и/или унифицировать с `resolve_index_path()`.
